## Experimental design

- Exactly one track: Track 1 (memory management).
- Trace: 4,000 requests over 32 pages; shift at zero-based index 2,000.
- Before: 85% references uniformly drawn from eight hot pages; other references sequentially cycle over 24 background pages.
- After: independent uniform draws from all 32 pages.
- Frames: 8, 12, 16. Evaluation seeds: 20–24; 60 policy/capacity/seed runs.
- Every policy and capacity receives the same generated trace per seed. Cache and feature history are retained at the shift. Cold-start faults are included.
- Separate training traces: seeds 0–7, 2,000 accesses each, three frame capacities.
- Oracle labels identify resident candidates with farthest next reuse; tied candidates all receive positive labels.
- Features: last-access recency, reference count over the preceding 64 accesses, residence age. No identifiers, shift labels, or future test information are features.
- Tree: depth 5, minimum 50 rows per leaf, balanced weights, random state 0. Train once; historical features update online. This is a learned policy, not online model retraining.
- Evict highest label-1 probability; ties use LRU, then smallest page ID.
- Means and sample SD over five test traces are reported. Error bars are SD, not confidence intervals.

## Actual simulation results

With 12 frames, before/after mean hit ratios are FIFO 68.90%/37.80%, LRU 80.25%/38.04%, Optimal 86.42%/67.20%, Learned 72.66%/36.99%. The learned tree does not consistently beat LRU. LRU's largest absolute decline reflects its stronger initial locality benefit. Under independent uniform requests, a causal cache with F distinct resident pages has expected hit probability F/32.

These results were actually generated by running the provided Python code in an assistant-operated Linux environment. They are **not** student-run Ubuntu/VMware measurements and are **not** measurements of kernel page faults. Machine metadata is in results/environment.json. No numbers are fabricated, and no claim of VM resource experimentation is made.

## Files and data dictionary

- `experiment.py`: workload generation, policies, oracle training, evaluation, tables and plots.
- `test_policies.py`: reference results, FIFO anomaly, independent exhaustive Optimal validation, accounting and no-future-leakage prefix check.
- `results/train_trace_*.csv`, `test_trace_*.csv`: complete page sequences; step is zero-based.
- `results/training_samples.csv`: candidate features, label, training seed, frame capacity. The feature/label pairs are sufficient to reproduce the classifier fit.
- `results/raw_steps.csv`: seed, frames, policy, step, page, phase, hit, fault, victim (blank for no eviction).
- `results/summary.csv`: per-seed/phase accesses, integer hits/faults, hit ratio.
- `results/aggregate.csv`: phase mean and sample SD for hit ratio and faults. Fractional mean faults are averages of integers.
- `results/hit_ratio.png`: all capacities, phases and policies with SD bars.
- `results/timeline.png`: 200-access window ratios at 12 frames, seed 20; illustrative, not an across-seed average.
- `results/decision_tree.txt`: fitted tree rules for inspection.
- `results/environment.json`: runtime/dependency metadata and seed manifest.
- `report/term_paper.tex`, `report/term_paper.pdf`: LaTeX source and PDF review draft with a cover page and three-page report body, with in-text citations and references.
- `DEMO.md`: 3–5-minute walkthrough and key explanations.
